## Pixel 7a 実機の不具合：画像が一切表示されない（KD-9）と単体HTML版
- **報告（ユーザー、実機）**：試遊ZIPを展開して `index.html` をAndroidのChromeで開くと、ロゴと全モンスター画像が壊れた画像アイコン＋代替テキストになる。ゲーム本体と手札は描画される。アドレスは `content://com.goo…` で始まっていた。
- **原因（推定）**：`content://` のURIで開いた場合、HTMLから相対パス（`paremon_monsters2/…`）で参照する画像は別リソースとして解決できない。**自動テストで再現済み**：同じHTMLを「URLなし・隣接ファイルなし」で開く（`setContent`）と、全画像が壊れる（`tests/standalone.test.mjs`）。PCの `file://` では問題が出なかったため、前回のテストでは検出できなかった。
- **対応（KD-9）**：ゲームと画像36点（ロゴ＋モンスター35枚）を**1つのHTMLに内蔵した「単体HTML版」**を追加（`tools/build_standalone.mjs`）。ゲームのルール・表示・操作の仕様は不変。複数ファイルのZIP版は互換用に残した。
- **取得**：CIの成果物 `paremon-playtest-standalone-<短いSHA>`（中身はHTML 1個、約6.8MB）。ダウンロード→展開→そのHTMLをChromeで開くだけ（隣にファイルは要らない）。
- **検証済み（PC）**：隣に何も無いフォルダの `file://`（393／412／PC）、URLなし（`setContent`）、全35種×7状態＋ロゴ＋詳細表示の画像、色調整中の画像切替、既存のルール・UI（KD-8の文字検査含む）・通しプレイ全件、外部通信なし、読み込み約0.6秒（CPUを4倍遅くしても約1.5秒）。**Pixel 7a の `content://` での表示は未確認**（PCでは `content://` を再現できず、「URLなし」で近似しただけ）。
- **残課題**：実機での確認。約6.8MB（画像PNGは元のまま。品質を下げる圧縮は行っていない）。
