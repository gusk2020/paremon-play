## 設計上の注意
- 状態を直接差し替えるテストは、毎回フラグを初期化する（前のテストの持ち越しを防ぐ）。
- ドラッグ直後400msはゲームがクリックを無視する仕様のため、固定待機ではなく `suppressCardClickUntil` の解除を待つ。
- デスクトップ高さではページが縦に伸びるので、ドラッグ前に手札と配置先が両方見える位置へスクロールする。
- 修正の有効性は「修正を外すと落ちる」ことで確認した（D-04：外すと3件失敗。KD-1/2/3・ロゴ代替テキスト：修正前のHTMLに戻すと新規9件が落ち、修正後は通る）。
- 画像の画素検査はブラウザのcanvasで行うため、`images.test.mjs` は小さな静的サーバ（`127.0.0.1`、テスト内で起動）経由で読む（`file://` の画像はcanvasが汚染される）。
- 画像・ロゴの再生成：`python3 tools/clean_assets.py --report`（numpy・scipy・Pillowが必要、開発時のみ。CIとゲームには不要）。常に `assets/originals/` から作り直す。
- 端の欠け（KD-4b）は `todo` として可視化している（元シートが無く直せないため）。`skip` にはしない。
