# パレットモンスター（パレモン）引き継ぎ書
作成日：2026/11/06（JST）

## 1. この企画の目的と進め方

実体カードを使うカードゲーム案から始まり、次は**スマートフォン上で実物カードの遊びをシミュレーションするゲーム**を作る。現時点では人に遊んでもらう予定はなく、本人の自己満足、好奇心、ChatGPT・Claude・Geminiなど生成AIの能力把握と活用経験を積むことが主な目的。

開発上の分担は次のとおり。

- ChatGPT：企画・仕様の整理、ユーザーとの窓口、GitHub管理、Claudeへの実装指示作成、Claudeのコード監査。
- Claude：ChatGPTが作った範囲の明確な指示に従ってコードを実装。
- Gemini：必要に応じて発散・比較案。
- GLM：必要に応じて単発レビュー。

スマートフォンを主な利用環境とし、画面と操作は小さな画面で触りやすくする。GitHubをコード管理に使う。対象リポジトリはまだ決まっていないため、既存の別ゲームのリポジトリを流用したり、存在を推測したりしない。公開・マージ・リリースはユーザーの明示指示なしに行わない。

## 2. 発想の経緯と独自化の方向

最初の案は、名前を「パレットモンスター」、略して「パレモン」とする、ポケモンのあからさまなパロディだった。最初に選ばれた遊びの核は「モンスターを集めて対戦」「色を組み合わせてモンスターを作る・変化させる」「育成・進化」の三つ。

その後、ポケモン固有の名前・絵・カード構成は使わず、独自の企画に移す方針を選んだ。残したいのは、よくできたカードゲームの操作性やパラメーター設計を参考にする姿勢と、色を混ぜる物理カードの発想。ルールの完全な模倣は目的ではないが、ユーザーはポケモンカードゲームに近いターン制・エネルギー管理・弱点処理の感覚を希望している。ゲーム固有のキャラクター、文章、カード枠、名称、ロゴは独自にする。

世界観は、色から生まれる生き物・精霊・自然現象がいる世界。プレイヤーは色を操る職人・画家・錬金術師の立場。色を組み合わせてモンスターを作る側であり、単に捕獲する側ではない。

## 3. 現在の仕様として受け取ったもの

### カードと創作

- 実体カードが出発点。スマートフォン版は、実物のカードと色混合台の体験を画面上で試すシミュレーターを目指す。
- プレイヤーのモンスターカードの山札には、印刷済みの完成モンスターと、自分で描いたり塗ったりしたモンスターの両方を入れる。
- モンスターの基礎能力とカード効果はルール上固定する。手描き・手塗りの上手さは強さや勝敗に影響させない。イラストがなくてもよく、色表示のみでも対戦・検討できる。
- 描画カードには、外形の枠、描く要素のお題、色の置き方、発想のヒントを載せたい。印刷済みのモンスターは、描かずに遊べる完成品と、手描きカードと同じルールで使える選択肢として用意する。
- 手描き用シートを紙・色鉛筆・ペン・透明スリーブ等のどれにするかは未決。試作しながら選ぶ。
- 色表示やシミュレーションは、イラストに頼らず**四角い色カード形状**で示す。色名・記号・数値も併記し、色だけで情報を伝えない設計を検討する。

### 色と混色

- 色相環は6色。仮の表示順は 🟥 → 🟧 → 🟨 → 🟩 → 🟦 → 🟪 →（🟥へ戻る）。
- 相性は輪の隣り合う色だけを見て、一方向の循環にする。現時点での向きは 🟥が🟧に強い、🟧が🟨に強い、🟨が🟩に強い、🟩が🟦に強い、🟦が🟪に強い、🟪が🟥に強い。各色は次の色に勝ち、前の色に負ける。
- 「短波長ほどエネルギーが強い」は世界観上のメタファー。色の物理的な強さを厳密にゲーム数値へ写す方針ではなく、循環相性を優先する。
- 加法混色（光を足す）と減法混色（色フィルター・インクが光を吸収する）の両方を遊びに取り入れたい。混ぜ方が違っても、最終的に同じ色になれば同じ色相・相性・効果にする。
- 色調整カードは、色相変更、カードに印刷された数値の反映、混色結果による能力変化に関わる案。視覚的な濃さだけで強さは決めず、カード記載の数値を使う。
- 色調整の効果は基本的に使ったターンだけ。あるカードが相性だけ・攻撃コストも・能力も変えるかは、個別カードの説明に明記する方向。
- 攻撃コストと相性は同じ色体系に結び付けたい。

### 対戦とターン

- 交互ターン制を希望。
- 自分・相手それぞれのモンスターカードの山札から引いて場に出し、手持ちの色調整カードとモンスター増強カードを使って戦う。モンスター数は固定せず、山札から出すイメージ。
- 1ターンに基本の色調整カードは1枚まで、増強カードは1枚まで。
- エネルギー方式はポケモンカードゲームに近いものを希望。手番に基本1枚のエネルギーをモンスターに付け、攻撃後も付けたまま残す。
- ワザの攻撃コストに色があり、色相環の相性と攻撃コストを結び付ける。コスト詳細は未決。
- 相性有利な側だけを強化する。ユーザーは弱点に対してダメージ2倍というポケモンカード方式を選んだ。不利側の抵抗力によるダメージ減少は採用しない。
- 勝利条件は「相手を規定数倒す」または「相手の全モンスターを倒す」のいずれかを先に達成する案。山札からモンスターを出し続ける方式なので、「全モンスター」の対象を山札・手札・場まで含めるか、出せなくなった状態と定義するかを決める必要がある。
- 最初の質問で育成・進化も選択されたが、現時点の対戦ループにどう組み込むかは未決。

## 4. 色カードだけで行った仮シミュレーション

色相相性の効果を比較するため、以下の仮数値を使用した。これは採用仕様ではなく、結果の違いを見るための例。

- A：🟥、攻撃2、体力7
- B：🟧、攻撃2、体力7
- Aが先攻、🟥は🟧に有利。イラストなし。
- 有利効果の候補として、ダメージ2倍・ダメージ+1・攻撃コスト-1を比較。
- 仮例では、ダメージ2倍が最も早く撃破、+1はその次、コスト-1は攻撃開始を早める展開になった。
- その後ユーザーは有利な側のダメージ2倍を選択し、不利な側への抵抗力減少は付けない方針を選択した。

今後のシミュレーションも、実物カードのように四角い色カードで表示し、仮数値・仮ルールは採用済み仕様と混同しない。

## 5. 実物・法的な障害の確認結果（2026/11/06時点）

### 実制作・色の表示

- 個人用のスマートフォン上の試作に、根本的な制作上の障害は見当たらない。
- 加法混色は色の光を足し、減法混色はフィルター・顔料が光を吸収する。物理では同じ見た目に揃うとは限らない。初期のスマホ版では、光学現象を厳密に再現するより、結果を6色の四角い色記号に対応させる設計が現実的。
- 将来発光台を作る場合は、RGB発光の加法モードと、白色光＋透明フィルターの減法モードを分けて試せる。光源、フィルター、印刷材で色が変わるため、実物の色見本と判定表が要る。
- 「目に優しい光」は主観的な表現。物理試作では光源を直視しない拡散構造と調光を検討するが、安全性・眼精疲労の不発生を保証する表現はしない。
- 短波長ほど光子エネルギーが大きいという説明は物理の比喩に使えるが、紫は単一波長ではなく赤と青紫側の光の混合で知覚される。世界観メタファーとして説明する。

### 権利・公開

- 日本での一般情報として、ゲームのルールやアイデアと、具体的な文章・絵・ロゴ・カードの表現は分けて考える。単なるアイデアは通常、著作権の対象ではない一方、具体的な表現は保護され得る。
- パロディだから自由に公開できるという包括的な例外は確認できない。個人用の試作と、画像投稿・配布・販売は別に扱う。
- ポケモンの公式絵・ロゴ・カード文面・固有キャラクターは使わない。カードの具体的な文章や枠、図案は独自に作る。
- 「パレットモンスター」「パレモン」は希望名・仮題として残すが、商標の空きは確認できていない。「パレモン」はポケモンを意識した響きなので、公開前にJ-PlatPatで文字・称呼の類似商標を調べる。公開するなら略称変更も比較する。
- 現在の「モンスターの山札・エネルギーを毎ターン付ける・弱点ダメージ2倍・撃破勝利」はポケモンカードゲームにかなり近い構造である。この類似自体が直ちに違法という判断ではないが、独自の世界・用語・カード文面・絵・カード枠・ブランド名を徹底する。
- ここまでの確認は一般情報であり、個別の法律判断ではない。

## 6. まだ決めていないこと

1. 場の構成：前衛1体＋控えか、複数体同時に戦うか。
2. 初期手札、山札枚数、引く枚数、モンスターを出す条件。
3. 規定撃破数と「全モンスター撃破」の正確な定義。
4. 6色の記号・色名と、カードの具体的な攻撃コスト対応。
5. HP・ワザの基本数値、増強カードの数値、ダメージ計算と先攻有利の調整。
6. 色調整カードが相性・攻撃コスト・能力のどこに影響するかを個別に設計。
7. 加法／減法混色の具体的な組み合わせ表と、スマホ上の色の見せ方。
8. 描画・塗り用カードの物理素材、スマホ版で手描き・塗りをどう扱うか。
9. 育成・進化の実装範囲。
10. プロジェクト名・リポジトリ名・GitHubの公開範囲。公開や配布は予定されていないが、後で希望が変わったら名称・商標確認を再実施する。

## 7. 次のChatGPT会話での進め方

引き継ぎ書の確定事項を聞き直さず、未決事項を優先度順に整理する。質問は一度に一つ、複数選択を許す。各質問には「実際のポケモンカードゲームではどうか」「一般的なカードゲームではどうか」を短く添え、必要なら公式情報を確認して出典を付ける。会話のシミュレーションは色の四角いカード表示を使う。

ユーザーが短い番号で答えても選択を正確に反映する。要件が固まったら、成果物を作る前に追加・変更要望を確認する。まずスマホで遊べる最小のデジタル縦切り版を設計し、AIへの外部実装指示は完成全文を一つのコピー可能なブロックにする。
